# i18n.md — bilingual conventions

Pro Care Qatar ships in English (LTR) and Arabic (RTL). Every URL has a
locale prefix; the design system is shared. This doc lists the rules that
keep the two locales in sync.

## Routing

Configured in `astro.config.mjs`:

```js
i18n: {
  defaultLocale: "en",
  locales: ["en", "ar"],
  routing: { prefixDefaultLocale: true, redirectToDefaultLocale: true },
}
```

- Every page lives at `/en/<route>/` or `/ar/<route>/`.
- Bare `/` redirects to `/en/` via `src/pages/index.astro`.
- Page files are thin wrappers around shared partials in
  `src/components/sections/`. There is no logic duplicated across locales.

## Translations

- `src/i18n/en.json` and `src/i18n/ar.json` are flat-keyed JSON with
  identical shape. **If you add a key to one, add it to the other in the
  same commit.**
- Read keys via `t(lang, "section.key")` (returns string, key string fallback)
  or `tn<T>(lang, "section.key")` (returns whatever shape the JSON value is).
- In Astro frontmatter you can use `tn<T>(...)`; in JSX template body, prefer
  `t(...)` — the JSX parser otherwise reads `<T>` as a tag.
- Do not concatenate strings to compose UI copy. Compose at the JSON layer or
  use a single translation key per piece of text.

## Direction

- `BaseLayout.astro` reads the locale from the URL and writes
  `<html lang dir>`. `dir="rtl"` for Arabic.
- Hooks: `useDirection()` in React islands, `getDir(lang)` in Astro
  frontmatter.
- **Always use logical properties** in CSS / Tailwind: `ms-`, `me-`, `ps-`,
  `pe-`, `start-`, `end-`. Not `ml-`/`mr-`/`pl-`/`pr-`/`left-`/`right-`.

## Direction-aware motion

Horizontal animations must respect the writing direction:

```ts
const { sign } = useDirection(); // 1 in RTL, -1 in LTR
gsap.to(track, { x: sign * distance, … });
```

The marquee is direction-aware via CSS only:

```css
[dir="rtl"] .marquee-track { animation-direction: reverse; }
```

## Fonts

Latin display + body share weight stems with `IBM Plex Sans Arabic`.
`global.css` swaps the family stack via `:lang(ar)` selector and drops the
display weight by one step (700 → 600) so Arabic glyphs don't look
artificially heavy at the same numeric weight.

Self-host the Arabic font with subset coverage `U+0600-06FF, U+0750-077F,
U+08A0-08FF, U+FB50-FDFF, U+FE70-FEFF` to keep the file ≤ 60 KB woff2.

## Adding a third locale

1. Add the code to `locales` in `astro.config.mjs`.
2. Add a JSON file under `src/i18n/<code>.json` with the same shape as
   `en.json`.
3. Mirror every `src/pages/en/*` page under `src/pages/<code>/*`.
4. If the locale is RTL, no extra wiring is needed beyond `getDir` —
   it returns `rtl` for `"ar"`. Extend the function for additional RTL
   locales.
5. Add the locale to the `LangSwitcher` (currently hardcoded for two).

## Verification checklist

- Tab through the page: focus order is correct in both directions.
- Marquee scrolls right-to-left in EN, left-to-right in AR.
- Horizontal services scrolls correctly (cards enter from the leading edge
  in both modes).
- Arrow glyphs flip via `rtl:rotate-180` where they indicate direction.
- Hreflang `<link rel="alternate">` tags point at the right alternate URL.
- `<html lang dir>` matches the URL prefix on every route.
